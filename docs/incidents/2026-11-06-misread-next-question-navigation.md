# 反思：答题卡「下一题」参照点理解错误（2026-11-06）

## 现象

首次实现「允许向后点一题」时，把「下一题」锚定在**当前正在浏览的题**上（`currentIndex + 1`）。
用户随后指出：要的是「已作答题目**的下一题**」，即已作答集合之后、首个未作答的前沿题，
而不是当前视图的后一题。

## 错误在哪

1. 需求原话「向后点击一题」天然有歧义：向后是相对「当前正在看的题」还是「已作答进度」。
2. 我没有在动手前确认参照基准，直接按视图游标 `idx + 1` 去实现。
3. 后果：当用户回看前面的已作答题时，`idx + 1` 仍落在已答区域内，真正该放行的「下一道待答题」没被放行。

## 修正

- 可点范围 = 所有已作答题 + 前沿题（首个未作答题）。
- 颜色语义：当前未答 = 虚线；当前已答（刚做完）= 粉色；已过去 = 绿色；前沿下一题 = 灰色虚线。

## 教训

1. 「下一题 / 后一题」这类导航词，先确认参照基准（视图游标 vs 作答进度）再动手。
2. 答题卡的可点范围应基于**作答状态的持久模型（已答集合 / 前沿）**，而不是瞬时的视图下标 `idx`。
3. 需求只有一句话且含歧义词时，宁可先问一句，也不要按最容易的实现方式猜。
